# 사용자 검토 문서

경로는 프로젝트 루트 `docs/user-review/<사용자가 요청한 주제>.md`. 이름에 경로 구분자나 Windows 금지 문자를 넣지 않는다. 별도 요청이 같은 제목이면 날짜 등을 붙여 구분한다. 본문은 한국어이고 Git 제외다.

```markdown
# 작업 주제

## 현재 진행 상황
- spec: 미착수 / 진행 중 / 완료 — 실제 문서 링크
- plan: 미착수 / 진행 중 / 완료 — 실제 문서 링크
- 구현: 완료 범위와 현재 작업
- 문서: 작성 위치와 초안·완료·대기 범위
- 검증·리뷰: 완료 근거와 대기 항목
- 중단 지점·다음 작업: 해당하는 경우만
- 마지막 갱신: 날짜·시각·시간대

## 사용자 확인
결정할 사항, 기다리는 작업, 답변 없이 진행 가능한 작업. 없으면 이 절을 생략한다.

## 검토안
목표·결과 동작 / 포함·제외 범위 / 중요한 구현 선택과 이유 / 영향·위험 / 검증·완료 기준
```

계획 세션이 작성한다. 상세 코드·파일 목록·변경 이력·대화 해설은 누적하지 않고 현재 결론으로 교체한다. 상태를 근거 없이 %로 표현하지 않는다. 설명 질문은 대화에서 답한다.

- spec·plan 초안 완성 시 이 문서를 갱신해 설치된 session.mjs preview 명령으로 표시한다. Neovim은 새 창으로, Codex 앱 원격은 stdout 본문과 문서 링크를 대화에 표시한다. 표시는 승인 아님.
- 추가 논의 후 반영할 문서와 내용을 확인하고 진행 지시 후 spec·plan·다른 문서를 작성·수정한다. 검토 문서도 갱신해 다시 표시한다.
- 구현·리뷰 중 중요한 결정이 있을 때도 같은 절차다. 단순 상태 갱신은 표시하지 않는다.
- 완료 시 결과·미검증·남은 항목을 정리하고 관련 문서를 반영하되 창을 다시 열지 않는다.
